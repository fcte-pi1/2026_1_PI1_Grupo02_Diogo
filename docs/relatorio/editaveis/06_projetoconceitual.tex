\chapter{Projeto Conceitual do Produto}

\section{Características gerais}

O projeto consiste no desenvolvimento de um \textit{micromouse}, capaz de percorrer um labirinto de forma autônoma e armazenar os dados do percurso em tempo real. O sistema utiliza sensores e algoritmos de navegação para tomada de decisão durante a exploração do ambiente.
Para a gestão do projeto, foi utilizada a Estrutura Analítica do Projeto (EAP), com o objetivo de organizar as atividades e definir as responsabilidades de cada integrante da equipe.
A equipe foi dividida em quatro áreas principais: eletrônica, software, estrutura e energia. Em cada uma dessas áreas, foi estabelecida uma hierarquia de atividades a serem desenvolvidas, permitindo uma melhor organização das tarefas e acompanhamento do progresso do projeto.

\begin{itemize}
    \item \textcolor{red}{ \textbf{Identificação dos Subsistemas Elétricos:} liste todos os componentes que consumirão energia, como sensores, microcontroladores, atuadores e módulos de armazenamento de dados. Para cada componente, registre a tensão de operação (V), corrente média (mA) e tempo estimado de uso (s).}
    \item \textcolor{red}{ \textbf{Cálculo da Energia Consumida por Componente:} utilize a fórmula: $E = V I t$, onde $E$ é a energia em joules, $V$ é a tensão em volts, $I$ a corrente em ampères e $t$ o tempo em segundos. Realize esse cálculo para cada componente do sistema.}
    \item \textcolor{red}{ \textbf{Estimativa do Consumo Total de Energia:} some as energias de todos os componentes para obter o consumo energético total estimado do sistema por lançamento.}
    \item \textcolor{red}{ \textbf{Escolha da Fonte de Alimentação:} com base no consumo total, converta para watt-hora: 1 Wh = 3600 J. Adicione e justifique uma margem de segurança (pesquisar o que é usual para este tipo de sistema) e selecione uma bateria ou fonte que supra a demanda.}
    \item \textcolor{red}{ \textbf{Planejamento do Circuito de Alimentação:} analise a necessidade de inclusão de reguladores de tensão, proteções contra sobrecorrente, e isolamento para atuadores. Como as oscilações de tensão serão controladas?}
    \item \textcolor{red}{ \textbf{Monitoramento via \textit{software}:} implemente, no \textit{software} embarcado, rotinas para medir a tensão da bateria e registrar dados de tempo de operação. Colete os dados para análise.}
    \item \textcolor{red}{ \textbf{Validação com Testes Reais:} realize testes de campo para comparar o consumo estimado com o real. Ajuste a capacidade da fonte se necessário e refine o software de coleta de dados. Justifique a diferença de resultados (real x teórica), de acordo com a literatura.}

Obs.: este é um diagrama sobre requisitos funcionais.}
    \item \textbf{Descrição da arquitetura da solução de \textit{software} proposta:}
    
    O \textit{software} atua como o núcleo de inteligência e monitoramento do sistema (Mission Control). Sua função é processar a telemetria enviada pelo robô em tempo real, gerenciar a construção dinâmica do mapa do labirinto, executar algoritmos de \textit{pathfinding} para determinar a rota otimizada e fornecer uma interface gráfica para visualização de métricas de energia e desempenho.
    
    \item \textbf{Estilo arquitetural contendo:}
    
    Arquitetura Orientada a Eventos (\textit{Event-Driven Architecture}) com Monólito Modular no \textit{backend}. Este padrão permite lidar com a natureza assíncrona dos dados de sensores, garantindo que o sistema reaja a eventos instantâneos sem latência perceptível. Como stack principal tem-se como:

    \begin{itemize}
            \item \textbf{Linguagens de programação:} JavaScript (ES6+) e C++.
            \item \textbf{\textit{Frameworks}, bibliotecas e protocolos:} 
            No \textit{front-end}, utiliza-se \textbf{React (Vite)} com \textbf{Tailwind CSS}. No \textit{back-end}, \textbf{Node.js}, \textbf{Express} e \textbf{Socket.io}. Para o \textit{firmware}, o \textit{framework} \textbf{Arduino} via \textbf{PlatformIO}. 
            % Adicionando a lista de protocolos aqui:
            A comunicação é regida pelos protocolos \textbf{MQTT} (entre ESP32 e Broker) para telemetria leve e \textbf{WebSockets} (entre Backend e Frontend) para atualização em tempo real.
            
            \item \textbf{Banco de dados:} Relacional \textbf{PostgreSQL} via Docker.
        \end{itemize}

        \item \textbf{Diagrama de alto nível:} 
        A arquitetura segue um fluxo de dados linear e reativo, conforme descrito abaixo:
        
        \begin{figure}[H]
            \centering
            \includegraphics[width=0.9\textwidth]{figuras/diagrama_arquitetura.png}
            \caption{Fluxo de dados e arquitetura da solução.}
            \label{fig:arquitetura}
        \end{figure}

    \begin{enumerate}
        \item \textbf{ESP32:} Coleta dados de sensores e publica pacotes JSON via \textbf{MQTT} no tópico \texttt{rato/telemetria}.
        \item \textbf{Broker Mosquitto:} Recebe as mensagens e as encaminha para os assinantes ativos.
        \item \textbf{Node.js (\textit{Back-end}):} Atua como assinante (\textit{subscriber}) do broker, processa os dados recebidos, realiza a persistência no \textbf{PostgreSQL} e emite eventos via \textbf{WebSockets}.
        \item \textbf{React (\textit{Front-end}):} Escuta os eventos emitidos pelo servidor e renderiza instantaneamente o labirinto e os gráficos de consumo energético.
    \end{enumerate}
